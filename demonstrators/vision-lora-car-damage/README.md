# Qwen2.5-VL 3B Car-Damage LoRA Demonstrator (pre-registration)

First-party run on the maintainer's Beelink GTR9 Pro (AMD Ryzen AI MAX+ 395, Radeon 8060S), started 2026-08-22.

**Status: completed. The pre-registration section below was written before any
evaluation or training run; the results were appended afterwards and the
acceptance criteria were not changed.**

## Purpose

Test, with a small public and reproducible experiment, whether a
vision-language model can be fine-tuned on a labeled image dataset and by
how much it beats its own zero-shot baseline: a zero-shot evaluation of an
off-the-shelf model on a labeled damage-classification image dataset, then
a LoRA fine-tune of the same model on the train split, both evaluated on
the same held-out test split.

## Fixed configuration (set before running)

- Hardware: Beelink GTR9 Pro, Ryzen AI MAX+ 395, Radeon 8060S, 128 GB.
- Container: `ghcr.io/justin-noel/amd-strix-halo-unsloth-toolboxes@sha256:8285eac06bf33398ad2605387e98d77eba30379cf690af755e238967ef238c3d`
  (same pinned image as the 2026-07-21 text LoRA campaign); Unsloth
  2026.7.3, PyTorch 2.13.0+rocm7.2, transformers 4.57.6, peft 0.18.1.
- Base model: `unsloth/Qwen2.5-VL-3B-Instruct` (bf16, no 4-bit), revision
  recorded in `versions.txt`.
- Dataset: `DrBimmer/comprehensive-car-damage` (MIT licence, manual
  annotations), revision `355b0990ec008e15963055e6bb448045a65040a3`,
  2,300 images, 6 classes: F_Normal 500, F_Crushed 400, F_Breakage 500,
  R_Normal 300, R_Crushed 300, R_Breakage 300.
- Split: per-class stratified, seed 42, 70% train / 10% val / 20% test.
  `manifest.csv` lists every image with split and SHA-256 and is frozen
  before any run.
- Task formulation: 6-way multiple choice with answer letters A-F
  (`scripts/common.py`); prediction = argmax over the six letter logits at
  the first generated position; confidence = softmax over those six.
  Deterministic, no sampling. Image resolution capped at 512x512 pixels
  for both baseline and fine-tuned evaluation.
- Fine-tune: LoRA rank 16, alpha 16, dropout 0, vision + language +
  attention + MLP modules, lr 2e-4 linear with 10 warm-up steps, batch 2
  x grad-accum 4, 2 epochs, seed 42, AdamW (torch), bf16. **Single
  configuration, no hyper-parameter search, no test-set peeking.**

## Pre-registered acceptance criteria

1. Primary: macro-F1 of the fine-tuned model on the held-out test split
   exceeds the zero-shot baseline by **>= 10 percentage points**.
2. Both evaluations run on the identical test split from `manifest.csv`.
3. Repeat evaluation of the fine-tuned model in a fresh process is
   reported (identical predictions expected; any numerical deviation is
   reported as-is).
4. Selective accuracy at 90% coverage (abstaining on the 10% least
   confident images) is reported for both models, as the bridge to the
   question of when a model should abstain and hand over to a person.
5. All failures, regressions per class, and negative findings stay in
   the report.

## Claim boundary

This is a methodology demonstrator: it shows that the dataset -> split ->
zero-shot baseline -> vision LoRA -> held-out evaluation -> repeat chain
works end-to-end on the maintainer's AMD hardware and produces a measurable
effect on a public labeled image dataset. It is **not** a claim about
repair-image diagnosis, musical instruments, production accuracy, or
state-of-the-art results: the dataset is car damage (a consumer-product
damage analogue), the model is small, and there is one run. Domain
transfer to real repair photos is the open question, not something this run answers.

# Results (appended 2026-08-23, criteria above unchanged)

All numbers below come from `report.md` / `metrics.json`, generated by
`scripts/04_report.py` from the committed per-image JSONL files.

## Headline

| metric (held-out test split, n = 460) | zero-shot baseline | LoRA fine-tuned |
|---|---|---|
| accuracy | 0.6326 | **0.7739** |
| macro-F1 | 0.5161 | **0.7555** |
| selective accuracy @ 90% coverage | 0.6715 | **0.8140** |
| accuracy on the abstained 10% | 0.2826 | 0.4130 |
| mean confidence | 0.717 | 0.813 |

- **Delta macro-F1: +23.94 points** against the pre-registered threshold of
  >= +10 points: **PASS** (criterion 1).
- Same frozen test split for both runs (`manifest.csv`, criterion 2).
- Repeat evaluation in a fresh process: identical predictions, confidence
  deltas 0.00e+00, **byte-identical JSONL** (criterion 3).
- Selective accuracy reported for both models (criterion 4): abstaining on
  the 10% least-confident images lifts fine-tuned accuracy from 77.4% to
  81.4%, and the abstained images are indeed much harder (41.3% accuracy)
  - the confidence signal carries usable information for an escalate-to-
  expert flow, while being far from calibrated perfection.

## Abstention on images (selective prediction)

`abstention.md` / `abstention.json`, generated by
`scripts/05_abstention_analysis.py` from the committed per-image JSONL.
Confidence is the softmax over the six answer-letter logits - a proxy,
not a calibrated probability; the calibration numbers say how far off.

| coverage (answered share) | zero-shot accuracy on answered | fine-tuned accuracy on answered | fine-tuned accuracy on abstained |
|---|---|---|---|
| 100% | 0.633 | 0.774 | - |
| 90% | 0.671 | 0.814 | 0.413 |
| 80% | 0.707 | 0.848 | 0.478 |
| 70% | 0.730 | 0.873 | 0.543 |
| 50% | 0.791 | 0.930 | 0.617 |

Expected calibration error (10 bins): 0.095 zero-shot -> **0.049**
fine-tuned; Brier score 0.206 -> 0.142.

Reading: after fine-tuning the confidence signal is informative enough to
drive an escalate-to-human flow - holding back the 30% least confident
images raises accuracy on the answered 70% to 87%, and the held-back
images are genuinely harder (54% accuracy). It is not a calibrated
uncertainty estimate (ECE 0.049 on one dataset, no temperature scaling,
no conformal guarantee); selecting thresholds and validating coverage
targets on the real domain remains open work.

## What changed per class (criterion 5: failures stay in)

The zero-shot model separated front/rear and damaged/undamaged well, but
almost never predicted "crushed": recall 0.07 (front) and 0.02 (rear).
After fine-tuning: F_Crushed recall 0.70 (F1 0.13 -> 0.70), R_Crushed
recall 0.53 (F1 0.03 -> 0.57). R_Crushed remains the weakest class
(precision 0.62) and is mostly confused with R_Breakage; F_Breakage recall
dropped slightly (0.87 -> 0.79) as the model stopped over-predicting it.
Full confusion matrices are in `report.md`.

- 1,610 train images, 2 epochs, 404 optimizer steps, batch 2 x 4

- Wall time 62.5 min on the Radeon 8060S (0.859 samples/s, ~5.7 s/step);
  mean train loss 0.149, last logged losses ~0.005 (`logs/logs_train.txt`,
  `adapter-meta/trainer_state.json`).
- Adapter: 164,458,848 bytes, SHA-256

  (kept in the maintainer's host artifact directory, not committed).


## Claim boundary (restated)

This demonstrates the dataset -> split -> zero-shot baseline -> vision LoRA
-> held-out evaluation -> repeat chain end-to-end on the guide's AMD
hardware, with a measurable and pre-registered effect on a public labeled
image dataset. The dataset is car damage, not repair cases of musical
instruments; the model is small; there is one training run and no
hyper-parameter search; the validation split was not used. Domain
transfer to real repair imagery, label quality, and calibrated abstention
thresholds are open questions that this run does not answer.
